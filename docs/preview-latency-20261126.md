# Android 预览出框延迟优化

2026-11-26。用户反馈安卓出文档框明显慢于扫描全能王。本次完成预览检测和显示等待的优化，生成可覆盖安装的 ARM64 Release APK。手机尚未重新连接 ADB，因此本轮没有真机相机耗时或与扫描全能王的同场景对照。

后续状态：同日手机重新连接，完成目标排序修正和真机算法回放，并已覆盖安装整合后的 Release 包。当前交付物及真机结果见 [预览文档目标选择修正](document-selection-20261126.md)；下面保留速度优化阶段的历史测量。

原实现要求连续三帧、持续至少 180 ms 才显示首次选框。Android 按 120 ms 采样，即使首帧已经检测成功，仍要额外等待至少 240 ms。现在首个有效候选立即显示，确认前标记为 `geometryFresh=false`；它不参与下一帧的优先选框，漏检后立即消失，也不能推进自动拍摄倒计时。确认后的选框继续使用原有位置替换确认、平滑和 360 ms 漏检容错，自动拍摄仍要求 900 ms 稳定及原有质量检查。

桌面 CPU 采样中，膨胀操作占 344/684 个分析样本，区域遍历占 219/684。新的 `BinaryMorphology` 将 32 个像素打包成一个整数，用移位和按位或完成同一方形邻域膨胀；同时复用半径 1 的膨胀结果，减少重复计算，并将加权平滑改为保留完整整数精度的可分离计算。检测分辨率、四组阈值、完整外框选择和四边支持检查保持原有规则。Android 采样间隔调整为 80 ms，继续只处理最新帧。

测量使用同一张保留的相机截图，缩至 360×480 并转为灰度。Android 两版都运行 Debug 代码，在同一个 API 36 ARM64 模拟器中测量；采样时没有并行构建。以下耗时只包含算法分析，不包含相机启动、对焦、取帧和界面绘制。

| Android 模拟器测量 | 修改前 | 修改后 |
|---|---:|---:|
| 检测耗时中位数 | 89.84 ms | 53.33 ms |
| 整帧分析耗时中位数 | 98.94 ms | 58.77 ms |
| 整帧分析 P95 | 133.60 ms | 63.26 ms |
| 首次整帧分析，单次观测 | 313.28 ms | 172.44 ms |
| 检测成功后首次显示额外等待，120 ms 采样 | 240 ms | 0 ms |

整帧分析中位耗时减少 40.6%。独立桌面 JVM 按改前、改后、改后、改前交替运行，两轮中位数的均值从 36.34 降至 18.60 ms。桌面测量用于验证算法成本，不能代表手机速度；首个有效框立即显示也不意味着相机打开瞬间即可出框。

原稳定性回放的 48 个输入逐帧 SHA-256 一致。改前从第 3 帧显示，改后从第 1 帧显示；第 3 帧起，确认坐标和新鲜状态完全一致。两版角点位移超过 0.08、面积变化超过 35% 的次数均为 0，最大相邻角点位移均为 0.01152。四个旋转方向的截图检测坐标完全一致。这段回放是经过橙色描边掩膜和修补的录屏裁剪，保留了部分原界面覆盖层，属于处理后的录屏输入；原始视频没有修改。

Android 79 项、iOS 80 项测试全部通过，iOS ARM64 目标编译成功。新增测试验证首次选框不能推进自动拍摄、孤立候选不被保留、较快采样仍须满足确认时长，以及位打包膨胀在图像边界、32 位字边界、反色和不同密度输入下与直接邻域定义完全一致。Android 原生同输入测量通过。
